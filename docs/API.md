# Tempo API

Base URL: `http://localhost:3001` (dev). All endpoints are versioned under
`/v1`. Interactive OpenAPI docs are generated by the API itself at **`/docs`**.

## Conventions

- **Auth**: `Authorization: Bearer <Clerk session JWT>` on everything except
  `GET /v1/health` and `GET /v1/share/:slug`. In local dev without Clerk keys,
  set `AUTH_DEV_BYPASS=true` (never active in production).
- **Validation**: request bodies/queries validated by zod schemas from
  `@tempo/types` (the same types the web client compiles against). Errors are
  `400` with `{ message, issues: [{ path, message }] }`.
- **Rate limiting**: 200 requests/min/IP (dev defaults).
- **Pagination**: cursor-based — pass `cursor` from the previous page's
  `nextCursor`.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/health` | liveness (public) |
| GET | `/v1/users/me` | profile + settings |
| PATCH | `/v1/users/me/settings` | update thresholds / board theme / language |
| POST | `/v1/games` | import PGN (paste or upload; multi-game) |
| GET | `/v1/games` | list, filters: `source`, `result`, `analysed`, cursor pagination |
| GET | `/v1/games/:id` | full detail: moves, analysis, opening |
| DELETE | `/v1/games/:id` | delete game + analysis |
| POST | `/v1/games/:id/share` | create/return public share slug |
| DELETE | `/v1/games/:id/share` | revoke share slug |
| GET | `/v1/share/:slug` | shared game (public) |
| POST | `/v1/imports/lichess` | queue Lichess username import `{ username, max }` |
| POST | `/v1/imports/chesscom` | queue Chess.com username import |
| GET | `/v1/imports` | recent import jobs |
| GET | `/v1/imports/:id` | job progress (poll) |
| PUT | `/v1/games/:id/analysis` | submit raw position evals (incremental batches) |
| GET | `/v1/games/:id/analysis` | current analysis state |
| GET | `/v1/evals?epds=a,b,c` | shared eval-cache lookup (≤ 200 EPDs) |
| GET | `/v1/stats/dashboard` | dashboard aggregates |

## The analysis contract (ADR 007)

Clients submit **positions**, not conclusions:

```jsonc
PUT /v1/games/:id/analysis
{
  "engineId": "stockfish-18-lite-wasm",
  "targetDepth": 16,
  "positions": [
    {
      "index": 0,              // 0 = starting position, i = after ply i
      "depth": 16,
      "lines": [               // MultiPV, best first; white-POV scores
        { "moveUci": "e2e4", "cp": 30, "pv": ["e2e4", "e7e5"] },
        { "moveUci": "d2d4", "cp": 22, "pv": ["d2d4"] }
      ]
    }
  ]
}
```

- Batches are incremental and idempotent; the response is the full derived
  `AnalysisDto` (classifications, accuracy, summary) up to the contiguous
  `lastPly` frontier.
- Terminal positions use `"moveUci": "none"` with a game-over score.
- Depth is monotonic: a submission can never downgrade a stored evaluation.
